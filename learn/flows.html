RAG pipeline

Retrieval-augmented generation prepares a corpus, then answers a question from what retrieval returned (Lewis et al., 2020). Use one embedding model at index time and at query time.

  1. Step 1

    Ingest

    Accept the document, its source, its date, and who may read it. Keep the original passage. A vector does not replace it.

  2. Step 2

    Chunk

    Split the document into passages you can return on their own. Overlap the edges so a cut sentence survives in one chunk.

  3. Step 3

    Embed

    Map each chunk with a single embedding model. Record that model’s name. Another model is another space.

  4. Step 4

    Index

    Store the vector, the passage, and the filter fields. An exact scan is honest. Approximate search is a measured trade.

  5. Step 5

    Retrieve

    Embed the query the same way and take the top k. A lexical ranker such as BM25 can run beside the vectors.

  6. Step 6

    Rerank

    Rescore the short list, often with a cross-encoder. Spend that cost on dozens of hits, not on the whole corpus.

  7. Step 7

    Generate

    Answer from the question and the passages you kept. If those passages are silent, say that they are silent.

  8. Step 8

    Cite

    Point each material claim at a retrieved passage. A pointer still has to be checked against the words it names.

Agent loop

The loop is plan, act with tools, observe, reflect, and stop. ReAct (Yao et al., 2023) is one published way to interleave a reasoning note with an action. The host executes tools. The return arrow means the goal is not met yet and the budget is still open.

  1. Step 1

    Plan

    Name the goal, the constraint, and what done means.

  2. Step 2

    Act with tools

    The model proposes a call. The host checks it, then runs it.

  3. Step 3

    Observe

    Record the result, including errors and empty answers.

  4. Step 4

    Reflect

    Compare the result with the goal. Keep the plan, revise it, or stop.

Stop condition. End the loop when the goal is met, a step or cost budget is spent, the same error repeats, or the next action needs a person. A loop that waits for the model to feel finished does not have a stop.
